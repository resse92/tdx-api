## Purpose

为 MAC 板块列表和板块成分提供可持久化的本地数据源，通过北京时间定时刷新与缓存缺失回源降低上游依赖，同时保留最近一次完整可用的数据。

## ADDED Requirements

### Requirement: 板块数据持久化
服务 SHALL 将成功获取的板块列表和每个板块的成分持久化，并 SHALL 在进程重启后继续使用已有数据。每类数据 MUST 记录最近一次成功更新时间，且写入中的数据不得被并发读取为不完整结果。

#### Scenario: 重启后读取已有数据
- **WHEN** 服务重启且持久化存储中已有成功写入的板块数据
- **THEN** 服务无需先请求上游即可读取该数据

#### Scenario: 并发读取刷新数据
- **WHEN** 板块数据正在被刷新且同时发生读取
- **THEN** 读取方获得刷新前的完整数据或刷新后的完整数据，不得获得部分写入结果

### Requirement: 北京时间定时刷新
服务 SHALL 使用 `Asia/Shanghai` 时区每天在 09:00、15:00、20:00 各启动一次刷新。每次刷新 MUST 从上游获取完整板块列表，并获取列表中每个板块的完整成分；同一进程内不得并发执行多个刷新周期。

#### Scenario: 到达刷新时间
- **WHEN** 当前北京时间到达每日 09:00、15:00 或 20:00
- **THEN** 服务启动一次板块列表及其全部板块成分的刷新

#### Scenario: 刷新跨越下一个触发时间
- **WHEN** 前一个刷新周期尚未结束且到达另一个计划触发时间
- **THEN** 服务不并发启动第二个刷新周期，并记录跳过事件

#### Scenario: 进程启动不在刷新时间
- **WHEN** 服务启动时持久化存储为空且当前时间不是计划刷新时间
- **THEN** 服务不因启动主动执行全量刷新，后续读取按缓存缺失规则回源

### Requirement: 缓存缺失回源
服务 SHALL 优先读取已持久化的板块数据。仅当所请求的板块列表没有任何记录，或指定板块没有任何成分记录时，服务 MUST 请求对应 MAC 上游；成功结果 MUST 在返回调用方前持久化。对同一缺失资源的并发读取 MUST 合并为一次在途上游请求。

#### Scenario: 板块列表缓存命中
- **WHEN** 调用方请求板块列表且存储中已有板块记录
- **THEN** 服务从持久化数据返回结果且不请求板块列表上游

#### Scenario: 板块成分缓存缺失
- **WHEN** 调用方请求指定板块且存储中没有该板块的任何成分记录
- **THEN** 服务请求该板块的上游成分，成功持久化后返回结果

#### Scenario: 同一资源并发缺失
- **WHEN** 多个请求同时读取同一个无缓存板块
- **THEN** 服务只执行一次该板块的上游请求，其他请求共享其结果

### Requirement: 刷新失败保留旧数据
定时刷新 SHALL 仅在板块列表及其全部板块成分均成功获取后发布新一代数据。任何上游请求或持久化操作失败时，服务 MUST 保留刷新前的完整数据，并记录失败阶段和原因；失败刷新不得使 HTTP 服务退出。

#### Scenario: 部分板块刷新失败
- **WHEN** 新板块列表获取成功但任一板块成分获取失败
- **THEN** 服务不发布本次刷新中的任何部分数据，并继续提供上一代完整数据

#### Scenario: 首次回源失败
- **WHEN** 对无缓存资源的上游请求失败
- **THEN** 服务不写入空结果，并将标准上游错误返回调用方

### Requirement: 存储生命周期
服务 MUST 在开始接受 HTTP 流量前打开并初始化板块存储；存储无法打开或初始化时 MUST 阻止应用启动。服务关闭时 SHALL 停止新的调度触发，取消或等待在途刷新，并在 HTTP 请求排空后关闭存储。

#### Scenario: 存储初始化失败
- **WHEN** 配置的持久化位置不可写或存储结构无法初始化
- **THEN** 应用返回明确启动错误且不开始接受 HTTP 流量

#### Scenario: 刷新期间关闭服务
- **WHEN** 应用在定时刷新执行期间收到关闭信号
- **THEN** 服务停止新的刷新并在关闭期限内取消或等待当前刷新，然后安全关闭持久化存储和上游连接
