## Context

当前主市场和 MAC 的 K 线 HTTP 处理器将客户端传入的分页参数直接交给各自的 `tdx` 调用。变更涉及两个协议适配入口、共享请求校验和 OpenAPI，因此需要统一日期范围语义，同时保留 `internal/tdx` 对 gotdx 连接和协议参数的所有权。具体外部行为以 `specs/main-market-http-api/spec.md` 和 `specs/mac-market-http-api/spec.md` 为准。

## Goals / Non-Goals

**Goals:**

- 在 `internal/httpapi` 统一解析 `start_date`、`end_date`：日线及以上周期使用 `YYYYMMDD`，日线以下周期使用 `YYYYMMDDhhmmss`，按北京时间解释并包含起止边界，在调用上游前完成校验。
- 在 `internal/tdx` 或其上游编排边界集中完成日期范围到 `offset+limit` 的转换，避免两个协议实现各自解释日期。
- 使返回结果最终按日期范围过滤并保持 gotdx 上游顺序，覆盖周末、节假日和空结果等交易日缺口。
- 通过 fake 上游验证换算参数、输入拒绝、响应过滤、上游错误透传和请求上下文取消；更新 OpenAPI，使公共契约与实现一致。

**Non-Goals:**

- 不修改 gotdx、连接池、重试、故障转移或优雅关闭机制。
- 不增加新的 K 线周期、市场、证券代码格式或实验性协议参数。
- 不保留 `offset`/`limit` 的兼容别名，不改变 K 线响应字段和统一响应结构。
- 不引入外部交易日历服务或新的运行时依赖。

## Decisions

### 统一日期 DTO 和校验边界

`internal/httpapi` 为所有受影响的 K 线请求使用按周期选择的日期解析规则：日线及以上日期必须为 `YYYYMMDD`，日线以下日期时间必须为 `YYYYMMDDhhmmss`，使用 `Asia/Shanghai` 解释，且 `start_date <= end_date`。K 线请求显式出现 `offset` 或 `limit` 时按未知/禁止参数返回 HTTP 400。校验通过后向内部调用传递类型化日期范围，而不是把原始查询字符串继续向下传递。

选择在 HTTP 边界校验，而不是让 gotdx 适配器处理字符串，是为了阻止非法输入触达上游并确保主市场、MAC 的错误码一致。旧参数不做兼容解析，因为规格明确这是一次破坏性公共 API 迁移。

### 集中式日期范围分页规划

新增小型、无连接所有权的日期范围分页规划逻辑，按 K 线周期计算从最新数据起点到 `end_date` 之前的偏移上界，再计算覆盖 `start_date..end_date` 的请求数量。由于上游分页按可用 K 线而非自然日计数，规划器采用自然日跨度的保守窗口并在返回数据未覆盖目标边界时按有限次数扩大窗口；最终结果必须在服务侧过滤到包含起止日期的范围内。规划结果仅转换为 gotdx 所需的 `offset+limit`，不新增公共协议字段。

选择集中规划并服务侧过滤，而不是让两个 HTTP 处理器各自按自然日直接换算，是为了统一周末/节假日处理和最大窗口限制。选择有限扩大而不是引入交易日历依赖，是为了保持无状态服务和现有部署不变；达到最大窗口仍无法覆盖时按既有上游错误/不完整结果契约处理并记录诊断信息。

### 保持协议适配器和连接生命周期边界

主市场和 MAC 的现有 `tdx` 客户端继续拥有 gotdx 连接、并发控制、超时和错误分类。日期规划只接收周期、日期范围和服务边界，调用方通过现有接口执行一次或有限次上游请求；每次请求继续使用原始 `context.Context`，不得创建绕过连接池的客户端。上游超时、不可用和取消仍映射为现有标准错误。

### OpenAPI 与测试同步更新

更新生成源和 `docs/openapi.json` 中全部受影响 K 线操作的参数：删除 `offset`、`limit`，增加必填 `start_date`、`end_date` 及格式、范围和 HTTP 400 说明。采用表驱动规划器测试、`httptest` 参数测试和 fake gotdx 调用断言，不依赖真实 TDX 网络。

## Risks / Trade-offs

- [没有外部交易日历时自然日无法精确映射交易日] -> 使用保守窗口、服务侧日期过滤和有限扩大，并设置最大请求边界；记录未覆盖边界的诊断信息。
- [历史范围较大时可能增加上游请求量] -> 复用现有数量限制，限制扩大次数和窗口大小；拒绝超过允许跨度的请求。
- [客户端迁移期间仍发送旧参数] -> 明确按 HTTP 400 拒绝，OpenAPI 和迁移说明同步发布，避免静默改变语义。
- [主市场与 MAC 实现出现分页换算差异] -> 共用日期校验和规划测试矩阵，并在两个协议的 fake 上游测试中分别断言最终参数。

## Migration Plan

1. 先发布包含新 OpenAPI、日期参数校验和适配器测试的版本，通知调用方将 K 线请求迁移到 `start_date`/`end_date`。
2. 部署后观察 HTTP 400 的旧参数请求、日期规划边界和上游超时/不可用日志；不改变连接或容器配置。
3. 若需回滚，部署上一版本并恢复调用方使用 `offset`/`limit`；新版本不写入持久化数据，因此无需数据迁移或回滚脚本。
